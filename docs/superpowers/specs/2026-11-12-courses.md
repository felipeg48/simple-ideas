# Courses: tutorials, slides, videos, labs and instructor demos

Status: spec, decided with the founder on 2026-11-12; not built. Four phases.

## Why

A course is what si already makes, put in order: readings (articles), slides
(decks that can present themselves), videos (filmed demo scripts, narrated
decks, any .mp4), labs (`type: lab`) and instructor demos (`type: demo`
runbooks), plus quizzes and progress. It must ship as a website bundle, as a
SCORM package any learning platform imports, and straight to SkillJar through
its API (more platforms later).

Greg's review (2026-11-12) of a guide in the crdb theme: the side menu's text
was too faint and its hover only recoloured that text. The contents column
was fixed in v3.1.5; the menus get the same treatment here, plus layouts.

## Phase 1: the course, its navigation, the website bundle

### A folder with `_course.md`

```markdown
---
title: CockroachDB for Python developers
description: Connect, write, retry and scale from Python.
level: intermediate
duration: 4h
nav: left · accordion · sticky
theme: studio
---
- Module 1: Connecting
  - [Why CockroachDB](01/intro.md)
  - [The architecture](01/architecture.md)
  - [Your first query](01/first-query.mp4)
  - [Demo: a node goes down](01/demo.md)
  - [Lab: connect and retry](01/lab.md)
  - [Check yourself](01/quiz.md)
- Module 2: Transactions and retries
  - …
```

- Modules are the top-level list items; lessons are the links under them.
- A lesson's kind comes from what it links to: an article or page →
  **reading**; a deck (`type: deck`, the default for a talk) → **slides**
  (embedded, with auto-play voice available); a `.mp4`/`.webm`, a demo script
  with `app:` (filmed by si, its `<script>.mp4` used) → **video**; `type:
  lab` → **lab**; `type: demo` without `app:` → **instructor demo**; `type:
  quiz` → **quiz** (phase 2). `· kind=…` after a link overrides.
- Each lesson may set `minutes:` in its front matter (else estimated: reading
  time, a deck's `(N min)` notes, a video's length, a lab's steps); module and
  course totals are shown.
- `prerequisites:` on a module or lesson (optional, shown, not enforced in
  phase 1).
- `si new <name> --type course` scaffolds a small course with every kind.
- `si check` checks the course: links, kinds, missing files, minutes.

### Two audiences

- **Learner build** (default: `si build course/`, `si serve course/`):
  readings, slides, videos, labs, quizzes. Instructor demos are left out of
  the menu, or shown as a placeholder "Your instructor shows this live"
  (`instructor-demos: show-placeholder` in `_course.md`). Slide decks show
  no speaker notes. Lab solutions are hidden (phase 2 reveals them on
  request).
- **Instructor build** (`si build course/ --instructor`, `si play course/`):
  everything, plus each demo's runbook (commands, expected output, talking
  points), the decks' teleprompter, module timings, lab solutions.

### Navigation layouts (courses, guides, books, sites)

`nav:` in `_course.md` / `_nav.md` / `_site.md` (or si.conf `nav:`):
- position: `left` (default for guides/courses), `right`, `top`, `bottom`
  (a phone-style bar);
- `sticky` (stays while the page scrolls) or not;
- `accordion` (one module open; clicking another opens it and closes the
  rest; the current lesson's module stays open), `tabs` (modules as tabs on
  `top`), `collapsed` (all closed but the current), `numbered`.
- Menu text at full strength (`--si-fg`), muted only for secondary info;
  hover = a tinted row + an accent bar (as the contents column, v3.1.5);
  the current lesson has a solid accent bar and tint.
- In a course: each module shows a progress ring and its minutes; each lesson
  its kind (a small labelled glyph, no emoji: Reading, Slides, Video, Lab,
  Demo, Quiz) and minutes.
- Fluid and responsive (rule #1): on a phone every navigator folds into a
  Menu button; `bottom` becomes the phone bar.

### The website bundle

- `si build course/ -o html/` writes one page per lesson plus the course
  home (title, description, level, duration, modules with their lessons,
  Start / Continue), with `--share-assets` behaviour by default for courses
  (one copy of shared scripts); `--zip` writes `<course>.zip` as well.
- Videos are copied beside the pages (never inlined; rule #2's media flag
  applies); a filmed demo script lesson runs `si demo run` only when its
  video is missing or older than the script, unless `--no-film`.

## Phase 2: quizzes, progress, lab solutions

- `type: quiz` pages (and a ```` ```quiz ```` fence inside any lesson):
  ```markdown
  ## Which isolation level does CockroachDB use by default?
  - [ ] Read committed
  - [x] Serializable
  - [ ] Snapshot
  > Explanation: serializable is the default; read committed is opt-in.
  ```
  single and multiple choice (`- [x]` marks the right answers), an
  explanation shown after answering, a score; a pass mark (`pass: 70%`).
- Progress in the browser (localStorage, per course): a lesson is done when
  read to the end, its video watched to 90 %, its lab's steps ticked, its quiz
  passed; ticks in the menu, rings per module, "Continue where you left off"
  on the course home; a completion page when everything is done (optional
  `certificate: on` with the learner's name typed in, printable).
- Lab solutions: a `<!-- solution -->` block in a lab is hidden behind a
  "Show the solution" button in the learner build, open in the instructor
  build.

## Phase 3: SCORM and printed handouts

- `si build course/ --scorm` writes `<course>-scorm12.zip`: an
  `imsmanifest.xml` (SCORM 1.2, the widest support: SkillJar, Moodle,
  Canvas, Docebo, Cornerstone), one SCO per lesson (or one for the course,
  `--scorm=single`), the pages calling the SCORM API (`LMSInitialize`,
  `cmi.core.lesson_status`, `cmi.core.score.raw` from quizzes, suspend data
  for progress); works offline; validated against the SCORM 1.2 schema in
  tests.
- `si build course/ --pdf`: a learner workbook (readings, lab steps, space
  for notes); `--instructor --pdf`: an instructor guide (demos with expected
  output, timings, answers, solutions).

## Phase 4: publish to SkillJar

- `si publish login skilljar` (API key, stored in `~/.si/publish.json`, 0600,
  never printed); `si publish course/ --to skilljar` (dry run unless
  `--yes`, as every `si publish`): create or update the course (title,
  description, level, duration), its modules and lessons in order; readings
  as HTML lessons, videos uploaded as video lessons, slides/labs/quizzes as
  web-package (SCORM) lessons; instructor demos never published; re-publish
  updates in place (ids kept in `.si/publish/skilljar.json` beside the
  course). Built against SkillJar's API documentation (check it before
  coding: endpoints, auth, upload limits); tests against httptest fakes only.
- `--to` stays open for more platforms later.
