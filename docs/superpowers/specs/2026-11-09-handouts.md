# Handouts: slides with notes or space to write, as one PDF

Status: DONE in v2.14.0. The founder changed the default during the build:
no speaker text unless asked (`slides` default; `lines`, `points`, `notes`).
It prints the deck page itself (`?si-handout=<mode>#print`) instead of a
separate renderer.

## Why

Courses and workshops (the CACI RabbitMQ course) hand out the deck: every
slide small, with the speaker's `Points:` beside it, or lines for the
reader's own notes, and a way back to the live deck. Today `--pdf` prints
one slide per page.

## What the author runs

```bash
si build talk.md --handout                  # handouts/talk.pdf: slide + Points:
si build talk.md --handout=lines            # slide + ruled lines for notes
si build talk.md --handout=grid             # 6 slides per page, no text
si build courses/ --handout --site "Course"  # every deck, linked from the index tiles
```

Front matter or si.conf can set it per deck: `handout: points|lines|grid`,
`handout-url: https://example.com/talk` (the QR target; default: none).

## The page

- A4 or Letter (from the locale, `handout.paper: a4|letter` in si.conf),
  portrait. Header: the deck title, author, date; footer: page numbers and,
  with `handout-url:`, a small QR code (`internal/qr`) and the address.
- `points`: three slides per page, each at the left (16:9) with its
  `Points:` at the right, in the theme's body font.
- `lines`: three slides per page with ruled lines at the right.
- `grid`: six slides per page, two columns, numbered.
- Each slide shows its final state (every build step revealed, like
  `?si-view=thumb`); canvases at their last state; 3D maps as their 2D view;
  videos as their poster.
- `Notes:` (the spoken script) is never in a handout: it is the speaker's.

## How it fits si

- A handout is a print page rendered by si (`render.Handout`): slide
  snapshots as live HTML scaled into fixed print boxes (print is the one
  place fixed sizes are fine: `@page` and `mm`, never on screen), then the
  headless-Chrome print `--pdf` already uses (`cmd/si` PDF path).
- Thumb rendering reuses deck.js `role === 'thumb'` (all steps shown).
- The index tile gets a HANDOUT badge next to PDF.

## Rules check

1. Screen output untouched; the handout is print-only, so `mm` and `@page`
   live in a print stylesheet that `TestLayoutHasNoFixedCanvas` exempts by
   name (`handout.css`).
2. One self-contained PDF.
3. RULES.md §14 (print) with an example; `examples/` gets `handout:` in the
   showcase front matter.
5. Points: in, Notes: out, by rule.

## Tests

- Render: the handout HTML (golden) for each layout.
- Build: `--handout` on the showcase produces a PDF with the expected page
  count (pdfinfo or a stdlib page count), and the QR on page 1 decodes
  (Vision, macOS, like `TestVision`).
- A look at the PDF, light theme and a dark-only theme (print forces light).
