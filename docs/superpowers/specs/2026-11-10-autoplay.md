# Auto-play: a deck that presents itself

Status: DONE v2.40.0 (all three phases), from the founder's idea on
2026-11-10; decided by the agent (full autonomy). Defaults chosen: key `v`,
dwell 3 s, `<deck>.voice/<slide>-<part>.m4a` (slide from 1, part from 0).

## Why

`Notes:` is already the speaker's exact words and `[CLICK]` already marks every
advance. With a voice (`si voice`, Kokoro `af_heart`), a deck can present
itself: read each slide's notes aloud, click where the notes say `[CLICK]`,
and move on. For a kiosk, a recorded talk, a rehearsal you listen to, or an
async share ("watch the talk").

## How it looks

- A **▶ Auto-play** button in the deck's bottom tools (beside overview,
  draw, teleprompter), a key (the first free one of `v`, `P`), and
  `#autoplay` in the URL (starts on load after one user gesture, as browsers
  require for sound).
- `si play deck/ --autoplay` opens the deck ready to auto-play (the button
  primed; `--open` starts it at once where the browser allows).
- While playing: a small bar with pause / resume / stop, the current line as a
  caption (toggle), and the slide's progress. Any navigation key, a click or
  the pen takes control back (auto-play pauses).

## What it says and when it clicks

- A slide's `Notes:` text (the `(N min)` hint and `[CLICK]` marks removed) is
  split at each `[CLICK]`: part 0 is spoken, then one advance (a build step or
  the next slide, the same action as → ), then part 1, and so on. After the
  last part the deck advances to the next slide.
- A slide with no notes stays for its `(N min)` share or 3 s
  (`autoplay.dwell` in si.conf), then advances.
- Two presenters (`speakers:`, `Notes[Name]:`): each part in its speaker's
  voice (`voice.<Name>: kokoro:am_michael` in si.conf or front matter
  `voices: Ada=af_heart, Ravi=am_michael`; default all `voice:`).
- `pronounce:` from front matter applies; captions keep the written words.
- Animated canvases, code shows and morphs run exactly as on a click.

## Where the audio comes from

1. **`si play`** (the server): `GET /_si/voice/<slide>/<part>.wav` voices the
   part with the deck's voice through `internal/webdemo` voice code (the same
   cache as `si voice say` and `si demo run`), so a re-run is instant and only
   edited notes are voiced again. Kokoro by default when installed, else the
   system voice; cloud voices with keys from the user si.conf.
2. **`si build --autoplay`**: voices every part at build time and writes
   `<deck>.voice/<slide>-<part>.m4a` beside the HTML (never inlined: an hour of
   talk would bloat the file); the page plays them by relative URL.
   `--autoplay=inline` inlines them for a single-file share (warn over 20 MB).
3. **No audio files** (a plain build opened from disk): the browser's own
   voice (Web Speech API, `speechSynthesis`), with a small "browser voice"
   label; still clicks on `[CLICK]`. Works offline.

The page asks for a part's audio; on 404 it falls back to Web Speech.

## Also

- `si build --mp4 --voice kokoro` (phase 2): a narrated video of the deck from
  its notes (reuses `--narration`'s timing path with generated audio).
- `si check`: notes with more `[CLICK]` than steps already warn; auto-play
  depends on that count, so the warning names auto-play.
- Teleprompter: shows "auto-play" and follows along.

## Phases

1. Runtime player (deck JS), `si play` voice endpoint, the button, key, bar,

2. `si build --autoplay` audio files; `voices:` per speaker.
3. `si build --mp4 --voice` narrated video.
