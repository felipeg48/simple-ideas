# Web demos: one script, a narrated video and a test

Status: decided with the founder on 2026-11-10. Phase 1 (test mode) built in
v2.34.0; phases 2 (video) and 3 (voice: system, kokoro, elevenlabs, openai;
piper, chatterbox and record not yet) in v2.35.0. The headline of **v3.0.0**.

## Why

si already drives headless Chrome over the DevTools protocol (stdlib only, no
Playwright): it films decks in real motion (`cmd/si/motion.go`) and took every
screenshot on simple-ideas.org. Pointed at a web application instead of a deck,
the same engine can perform a feature, film it, narrate it and check it.

One script, two results:

1. **A demo:** a narrated video of each feature of a web app, for a launch, a
   course, a changelog, YouTube.
2. **A test:** the same steps carry expectations, so the run reports what
   passed and what broke (step, screenshot, the seconds before, expected and
   found), with an exit code and a JUnit file for CI.

Retake (`~/Progs/AI/retake-app`) does the same for native Mac apps in Swift.
The two share the **script format** (this file is its source), not code.

## Founder decisions (2026-11-10)

1. Steps are **precise and repeatable** (no AI choosing what to click).
2. **Cloud voices from day one**, beside the free local ones.
3. **Secrets from environment variables** (`$SHOP_PASSWORD`), blurred when
   typed in the video.
4. **Both outputs:** one MP4 per feature *and* one full video with chapters.
5. **Callouts** in the video (notes pointing at an element, e.g. the demo login
   to use).
6. **Captions** of the narration: an `.srt` always, burned into the video with
   `--captions`.
7. **si's voice is Kokoro `af_heart`** (`voice: kokoro:af_heart`): the voice
   of si's own manual and site videos, and the default when Kokoro is
   installed (the founder picked it from samples on 2026-11-10; Kokoro made 8 s
   of audio in about 1 s on a laptop CPU). Without Kokoro, the computer's own
   voice.

## The script

A `type: demo` page (si's demo-script type grows this mode when the front
matter has `app:`). Markdown, AsciiDoc (converted as usual) or JSON (the same
structure, for tools).

```markdown
---
type: demo
title: Northwind Shop, the checkout
app: http://localhost:3000        # where the web app runs
viewport: 1440x900                # also: phone (400x800), tablet
voice: kokoro:af_heart            # engine:voice (see Voices)
setup: npm run seed               # optional: run before each feature (a known state)
---

## Pay for an order

What it does: a customer pays with a card and sees "Paid" at once.

Say: Sign in with the demo account.
- go /login
- note "Username: demo · Password: shop-demo" at "Username"
- type "demo" into "Username"
- type $SHOP_PASSWORD into "Password"
- click "Sign in"
- expect text "Welcome back"

Say: Open the order and choose Pay.
- go /orders/4711
- click "Pay"

Say: A test card goes through in a second.
- type "4242 4242 4242 4242" into "Card number"
- click "Confirm"
- expect text "Paid"
- expect url /orders/4711/receipt
```

- Each `##` is a **feature**: one clip, one chapter, one test case.
- `What it does:` is the feature's description (the video's title card, the
  report's summary, YouTube chapter text).
- Each `Say:` line narrates the steps under it, up to the next `Say:`.
- `Notes:` and `Points:` keep their si meaning (presenter text), unused here.

### Steps

| Step | What it does |
|---|---|
| `go /path` (or a full URL) | navigate; waits for the page to settle |
| `click "Pay"` | click the element a person would: visible text, label, aria name, title; or `#id`, `[data-testid=pay]`, `role=button "Pay"` |
| `type "text" into "Field"` | focus and type, at a human pace in the video |
| `type $VAR into "Field"` | from the environment; never written to logs, blurred in the video |
| `press Enter` · `press cmd+k` | keys and shortcuts |
| `select "Express" in "Shipping"` | a `<select>` or listbox |
| `check "Gift wrap"` · `uncheck …` | checkboxes and switches |
| `hover "Help"` · `scroll to "Footer"` | |
| `wait 1s` · `wait for "Saved"` | a pause in the video, or until something appears |
| `note "text" at "Element"` | a **callout**: a note pointing at the element, shown from here to the end of the `Say:` block (`· for 3s`, `· position right`) |
| `expect text "Paid"` | the page shows it (within a timeout) |
| `expect url /orders/4711/receipt` | |
| `expect "Pay" disabled` · `… visible` · `… hidden` | element state |
| `expect no errors` | no console errors and no failed requests so far |
| `screenshot name` | a named picture in the report (and the docs) |

A step that cannot find its element waits (default 5 s, `timeout:` in front
matter), then fails with the closest matches it saw.

## Two commands

```bash
si demo run shop.md            # the videos, the narration, captions, chapters, the report
si demo test shop.md           # the checks only: fast, no video; exit 1 on a failure; --junit report.xml
si demo run shop.md --feature "Pay for an order" --captions --viewport phone
```

### `si demo run`: what it writes (`demo-out/<script>/`)

| File | What |
|---|---|
| `<feature>.mp4` | the feature, video and voice mixed (H.264 + AAC) |
| `<feature>.video.mp4` | the same video, silent |
| `<feature>.voice.m4a` (and `.wav`) | the narration alone, to re-voice or edit |
| `<feature>.srt` | captions of the `Say:` lines, timed |
| `all.mp4` | every feature in one video, a title card per feature, chapters embedded |
| `chapters.txt` | YouTube chapter lines (`0:00 Pay for an order`) |
| `report.html` + `report.json` | the run (see the QA report) |
| `README.md` + `README.html` | what is in the folder: a table of every file, each feature with its video playing in the page, the script, how it was made (the founder asked for both, 2026-11-10; README.html is built by si itself, videos linked, not inlined) |

`--captions` burns the narration into the video (bottom, the theme's look,
two lines at most); without it, the `.srt` sits beside the video.

### How a take works

1. Parse the script; check it (`si check` knows the steps, the selectors'
   shape, `$VAR`s that are not set).
2. **The narration sets the pace.** Make every `Say:` line's audio first and
   measure it. Each block's steps are spread over its narration; a block whose
   steps need longer than its words waits for them.
3. Run `setup:` (if any) and open the app in headless Chrome at the viewport.
4. Perform each step, recording frames (the DevTools screencast, or the slowed
   page clock of `motion.go` for smooth motion), with a drawn cursor that
   glides to each target and a ripple on clicks, callouts and blurred secrets
   painted into the page as an overlay layer.
5. Encode with ffmpeg; mix the voice; write captions and chapters.
6. Check every `expect`; on a failure, stop that feature, keep the clip up to
   the failure, and write it to the report.

## The QA report

`report.html` (one self-contained page, si-themed) and `report.json`:

- per feature: passed / failed / skipped, its duration, its clip;
- per step: the step, the time it took, the screenshot after it;
- on a failure: expected and found, the closest elements it saw, a
  screenshot, the last seconds of video, the browser's console errors and
  failed network requests until then;
- the environment: app URL, viewport, Chrome version, si version, the date.

`si demo test` exits 1 when anything failed and writes `--junit file.xml` for
CI (GitHub Actions, GitLab, Jenkins all read it).

## Voices

`voice: engine:name` in front matter, or `--voice`. The engine makes the
audio; si measures and places it.

| Engine | Kind | Notes |
|---|---|---|
| `system` | the computer's own (`say` on macOS, SAPI on Windows, espeak-ng on Linux) | free, offline, always there |
| `kokoro` | open source (Apache 2.0), local | natural; the recommended free default when installed |
| `piper` | open source, local | tiny and fast, many languages |
| `chatterbox` | open source (MIT), local | expressive; clones a voice from a short sample |
| `elevenlabs` | cloud, `ELEVENLABS_API_KEY` | the most natural; voice cloning |
| `openai` | cloud, `OPENAI_API_KEY` | `gpt-4o-mini-tts`; a tone instruction (`voice-style: calm, friendly`) |
| `record` | your own voice | the teleprompter's ● Record per `Say:` line |

Local engines run as external programs (listed by `si doctor`, installed
once); cloud engines are plain HTTPS calls from Go (no SDK). Audio is cached by
the hash of its text and voice, so re-running a script only re-voices the lines
that changed. Cloud calls never send anything but the `Say:` text.

## Retake

The same script format, for a native Mac app instead of a URL:

- front matter `app: Notes` (an app name or bundle id) instead of a URL;
- the native steps (`menu File › New Note`, `key cmd+s`, `expect window
  "Groceries"`) beside the web ones; steps one tool does not know are an error
  in that tool, never silently skipped;
- the same `Say:`, `What it does:`, `note`, `expect`, voices, outputs, report.

This spec is the source; Retake's `CLAUDE.md` points to it and lists its
native steps. Shared example scripts serve as conformance fixtures for both.

## The manual, with videos

si's own help becomes demo scripts that drive the Studio (`si --web`) and the
decks: "make a deck", "the Theme view", "a theme from a logo", "present from
your phone". `make docs-videos` re-records them for every release; they double
as end-to-end tests of si itself, and the site and the README embed them.

Decided with the founder (2026-11-10):

- **Scripts in `docs/demos/`**, one per area; only scripts in git, never the
  videos.
- **Two CI jobs:** `si demo test docs/demos` on every push (fast, no video:
  si's own end-to-end test); `si demo run` films them on every **minor**
  release tag (`v2.N.0`, not patch tags) and on a manual `workflow_dispatch`.
- **Voice:** Kokoro `af_heart` in CI (`si voice install kokoro`, model files
  cached between runs). Same fonts installed in CI as the site uses; a few
  frames checked before the look is trusted.
- **Length:** a short clip per feature (20–40 s) plus one `all.mp4` per area
  with chapters. The site shows the full video at the top of each feature page
  and each clip beside its section, with captions (`si demo run` also writes
  `.vtt`, which browsers need) and chapters.
- **Where videos live:** the Pages build made on the tag (and the release's
  assets). The README shows a poster per area linking to the site's video
  (GitHub does not play videos from another site).
- **First batch (6):** a deck from nothing; presenting (keys, overview, draw,
  teleprompter); the Studio; a theme from a logo; mind maps; the terminal.

## How it fits si

- **Engine:** a `demo` package next to `cmd/si/motion.go`'s CDP client
  (stdlib), probably promoting that client to `internal/cdp`.
- **Script:** `internal/deck` parses the demo form (steps, `Say:`, `note`,
  `expect`) as data; `si check` reports a bad step with its line.
- **Overlay:** the cursor, ripple, callouts, blur and captions are an injected
  stylesheet and script in the page under test (removed between takes), drawn
  with si's theme tokens.
- **External programs:** Chrome and ffmpeg (already in `si doctor`), plus the
  chosen local voice engine (`tools` gains `kokoro`, `piper`, `espeak-ng`,
  `chatterbox`).
- Rules: stdlib + goldmark in Go; nothing in a built deck changes.

## Phases

1. **Test mode:** the script parser, the steps, `expect`, the report,
   `si demo test` with JUnit. No video, no voice: useful to developers at once.
2. **Video:** frames, the cursor and ripple, callouts, blur, per-feature and
   full MP4s, chapters.
3. **Voice:** the engines (system, kokoro, piper, elevenlabs, openai, record),
   narration-driven pacing, `.srt`, `--captions`.
4. **The manual with videos** (`make docs-videos`) and the site.
5. **Retake:** update its `CLAUDE.md` with the shared format and native steps.

## Lessons from the first prototype (2026-11-10)

A first take of the Studio (two features, 35 s, Kokoro af_heart) was made with
Playwright + kokoro-onnx + ffmpeg before the engine exists; its script is the
spec's format. What it taught:

- **`pronounce:`** is needed: Kokoro says "si" as "see". Front matter
  `pronounce: si = ess eye` changes what the voice says; captions keep the
  word.
- **Captions must be drawn by si**, not by ffmpeg: Homebrew's ffmpeg 9 has no
  `subtitles` or `drawtext` (no libass, no freetype). Rendering each caption as
  a transparent PNG and compositing with `overlay` (in every build) works.
- **Narration-first pacing works:** each block lasts max(its voice, its steps);
  the take came out with no dead air once steps stopped timing out.
- **A failing step must fail fast in a take:** a 30 s locator timeout left 30 s
  of nothing in the video. In `run`, a failure ends the feature's clip there.
- **Locators:** a hidden label (`aria-label`) is not "visible text"; the
  report's "closest matches" matters, both first failures were found that way.
- **ffmpeg in a loop** must get `-nostdin`; `-filter_complex_script` is gone in
  ffmpeg 9 (use `-filter_complex` with the text).
