Cockroach Education Platform — Architecture & Design

Docker-native lab platform · a Go control plane that is the scheduler · no Kubernetes, no per-session VMs

1The bet

Three load-bearing decisions. Everything else follows from these.

no k8s / no VMs

The control plane is the scheduler

A Go service drives the Docker Engine API directly — create network, start containers, wire the cluster, reap. We trade a managed orchestrator for a small, legible scheduler we own.

admission by RAM

Budget memory, not containers

RAM is the real ceiling. Each environment template declares a RAM cost; the scheduler admits against 0.9 × host_ram and queues when full — so a cohort never OOM-kills the host.

safe nesting

The lab box is a nested-Docker sandbox

The student deploys CockroachDB inside their own box — via docker compose, or on Kubernetes with K3d/kind. Prod runtime = sysbox-runc (unprivileged); demo = privileged DinD. Linux-only host.

2Request & networking flow

How a learner's browser reaches their private environment — through one Cloudflare tunnel and the gateway, routed by hostname.

Learner Edge / Cloudflare Control plane (cep-ops) Session container
Why one tunnel: a single cloudflared + wildcard DNS exposes every session without opening host ports. The gateway holds the token→session map and proxies WebSocket (required for the terminal). Demo shortcut: terminal via ttyd; later replaced by control-plane exec → WS → xterm.js.

3Control-plane components · cep-ops

One Go binary. The provisioner is the only thing that talks to the Docker Engine API.

Prohibited: bind-mounting the host Docker socket into an attendee container (that is host root). Only the control plane holds Engine-API access; attendees reach Docker — when a lab needs it — through the isolated Sysbox path below.

4Host & session isolation

One host, many sessions. Each student gets one nested lab box and deploys CockroachDB inside it. Pure-SQL labs can instead use a pre-provisioned cluster.

The right box is the default: the student deploys CockroachDB themselves inside a nested lab box — that's the teaching goal. The left (pre-provisioned) shape is the variant for SQL-only labs. Host note: Sysbox is Linux-only; for the demo use privileged DinD on a throwaway VM (trusted testers) and switch to Sysbox before untrusted attendees.

5Session lifecycle

A small state machine the scheduler and reaper drive.

6Domain model

Content is static per workshop version; environments are dynamic per session.

Workshop — slug, version, env_template_ref → Lessons.
Lesson — ordered, holds Steps.
Step — instructions_html, optional setup, optional check.
EnvironmentTemplate — workspace_image, topology (single/3/9), ports, limits, ttl, idle_timeout, runtime (default | sysbox).
Cohort — workshop_ref, seats, starts/ends, access_codes, reserved_capacity.
Session — cohort_ref, attendee_token, state, env_ref, progress.
Environment — session_ref, network_id, containers, expires_at.
Check — run, expect_exit?, expect_stdout_contains?.
Progress — session_ref, step_ref, status (todo/passed/failed).
Content pipeline: authors write source → the si tool renders HTML/markdown + a workshop.yaml manifest (lessons → steps → env template → checks) → cep-ops ingests it. Unconfirmed: the exact si output format — confirm before wiring ingest.

7Capacity, cost & the Phase-1 plan

RAM-bound, measured on Colima: a session is one nested-Docker box running 1–9 CRDB nodes (multi-region = more nodes in the same box, not more VMs). Data is tiny (~10M small rows, on disk), so RAM tracks node count: ~0.6 GB (1-node) · ~1.5 GB (3-node) · ~2.5 GB (9-node). Full write-up: hosting-and-cost.html.

Phase 1: one always-on 64 GB VM (e2-highmem-8), --mem-budget-gb 50 --mem-mb 2048 → 25 concurrent sessions, internal via LB + IAP on crdb.dev. Instant availability is required, so the host never stops; idle cost (~$250–300/mo) is accepted. Out: GKE (Autopilot can't run privileged DinD; Standard = VM cost + ~$73/mo cluster fee) and scheduled start/stop (breaks instant). Later: 1-node topology per track (~2–2.5× density), then a multi-host MIG.
